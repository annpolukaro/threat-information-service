# Threat Information Service

Небольшой REST API-сервис для хранения информации о компьютерных угрозах по MD5-хешу файла. Написан на Go, данные хранятся в PostgreSQL. HTTP-интерфейс основан на [OpenAPI-спецификации](api/openapi.yaml) из задания.

## Возможности

Сервис позволяет создавать записи об угрозах, получать их по MD5 и обновлять существующие записи. MD5 служит уникальным идентификатором: создать две записи с одинаковым хешем нельзя.

Входные данные проверяются перед сохранением. Для операций изменения данных требуется API-ключ. Запросы проходят через Nginx с HTTPS; также предусмотрены ограничение частоты запросов и тесты.

## Технологии

- **Go** — HTTP-сервер, обработка запросов и бизнес-операции.
- **PostgreSQL 17** — хранение записей об угрозах.
- **Docker и Docker Compose** — сборка и запуск приложения, базы и Nginx.
- **Nginx** — HTTPS и обратное проксирование запросов к Go-серверу.
- **OpenAPI 3.0** — описание доступных методов, моделей и ответов.
- **Go testing** — модульные и интеграционные тесты.

## Архитектура

Код разделён на три прикладных слоя:

1. **Handler (`internal/handler`)** — принимает HTTP-запросы, разбирает JSON, вызывает сервис и преобразует результаты и ошибки в HTTP-ответы. Здесь же находятся middleware авторизации и ограничения запросов.
2. **Service (`internal/service`)** — выполняет операции создания, получения и обновления угроз. Применяет правила валидации и нормализации модели перед обращением к репозиторию.
3. **Repository (`internal/repository`)** — выполняет SQL-запросы и работает с PostgreSQL.

В `internal/domain` находятся модель угрозы, допустимые значения полей и правила их проверки. Зависимости создаются в `cmd/server/main.go` в порядке `repository → service → handler`.

## Модель угрозы

Помимо исходных `md5` и `name`, модель содержит следующие поля:

| Поле | Назначение |
|---|---|
| `md5` | Уникальный MD5-хеш файла: 32 шестнадцатеричных символа |
| `name` | Название угрозы, обязательное поле, не более 255 символов |
| `description` | Дополнительное описание угрозы |
| `threat_type` | Тип угрозы: `trojan`, `virus`, `worm`, `ransomware`, `spyware`, `other` |
| `severity` | Уровень опасности: `low`, `medium`, `high`, `critical` |
| `first_seen_at` | Время первого обнаружения, если известно |
| `created_at` | Время создания записи |
| `updated_at` | Время последнего обновления записи |

MD5 приводится к нижнему регистру, пробелы по краям названия удаляются. Если тип угрозы не указан, используется `other`; если не указан уровень опасности — `medium`. Время передаётся в формате RFC 3339, например `2026-01-15T10:30:00Z`.

## Запуск через Docker Compose

Для запуска нужны Docker с поддержкой Compose и свободные локальные порты **80**, **443** и **15432**. Примеры команд ниже рассчитаны на **Windows PowerShell**. Выполняйте их из корня проекта.

### 1. Настроить переменные окружения

В репозитории есть файл `.env.example` — **шаблон**, а не готовая конфигурация с секретами. Скопируйте его в `.env`:

```powershell
Copy-Item .env.example .env
```

Откройте созданный `.env`. В нём должны быть следующие переменные (значения ниже — только пример):

```dotenv
POSTGRES_USER=threat_user
POSTGRES_PASSWORD=replace_with_your_db_password
POSTGRES_DB=threats_db
POSTGRES_PORT=15432

API_KEY=replace_with_your_long_random_api_key
```

- `POSTGRES_USER` — имя пользователя PostgreSQL; для локального запуска можно оставить `threat_user`.
- `POSTGRES_PASSWORD` — **замените** на собственный пароль базы данных.
- `POSTGRES_DB` — имя базы; можно оставить `threats_db`.
- `POSTGRES_PORT` — порт PostgreSQL на компьютере; по умолчанию `15432`.
- `API_KEY` — **замените** на собственный длинный случайный ключ. Его нужно передавать в заголовке `X-API-Key` при POST и PUT.

В `.env.example` ничего менять не обязательно: он нужен другим разработчикам как образец. **Не публикуйте `.env` и не отправляйте реальные пароли или API-ключи в репозиторий.** `DATABASE_URL` для контейнера API формируется в `compose.yaml` из переменных PostgreSQL автоматически.

> Если вы уже запускали PostgreSQL и позже изменили `POSTGRES_USER`, `POSTGRES_PASSWORD` или `POSTGRES_DB`, новые значения не переинициализируют существующий том базы данных. Для чистого запуска используйте отдельный том или удалите старый через `docker compose down -v` **только если данные не нужны**.

### 2. Создать TLS-сертификат и приватный ключ

Nginx ожидает два файла в папке `certs/`:

- `certs/server.crt` — сертификат сервера;
- `certs/server.key` — **приватный ключ** к сертификату.

Эти файлы нужно создать локально. Не вставляйте в них текст API-ключа из `.env`: TLS-ключ и API-ключ — разные вещи. Команда ниже создаёт самоподписанный сертификат для `localhost` и соответствующий приватный ключ:

```powershell
New-Item -ItemType Directory -Force certs | Out-Null

docker run --rm `
  -v "${PWD}:/work" `
  -w /work `
  alpine/openssl req -x509 -nodes -newkey rsa:2048 `
  -keyout certs/server.key `
  -out certs/server.crt `
  -days 365 `
  -subj "/CN=localhost" `
  -addext "subjectAltName=DNS:localhost"
```

Если сертификат и ключ уже созданы для локального запуска, повторять команду не нужно. Папка `certs/` исключена из Git через `.gitignore`; **приватный `server.key` нельзя публиковать**. Самоподписанный сертификат подходит для локального тестирования, но не для публичного развёртывания.

### 3. Собрать и запустить контейнеры

```powershell
docker compose up --build -d
docker compose ps
```

Compose запускает PostgreSQL, Go API и Nginx. PostgreSQL и API должны перейти в состояние `healthy`, Nginx — в `running`.

Если контейнер не запускается, посмотрите логи:

```powershell
docker compose logs --tail=100 postgres api nginx
```

### 4. Проверить работу сервиса

```powershell
curl.exe -k -i https://localhost/healthz
```

Ожидается статус `200 OK` и ответ:

```json
{"status":"ok"}
```

API доступен по адресу `https://localhost`. Параметр `-k` отключает проверку доверия к локальному самоподписанному сертификату; использовать его для публичных серверов не следует.

Остановить контейнеры можно командой `docker compose down`. Она не удаляет том с данными PostgreSQL.

## API

Полная спецификация находится в [`api/openapi.yaml`](api/openapi.yaml). Ниже — примеры использования основных операций. Для POST и PUT нужен заголовок `X-API-Key` со значением из **вашего** `.env`; GET доступен без ключа.

Для удобства задайте в PowerShell переменные (подставьте тот API-ключ, который указали в `.env`):

```powershell
$apiKey = "ВАШ_API_KEY_ИЗ_ENV"
$md5 = "5d41402abc4b2a76b9719d911017c592"
```

### POST `/info` — создать угрозу

Создаёт новую запись. MD5 должен быть уникальным. Подготовьте JSON в файле `create.json`:

```json
{
  "md5": "5d41402abc4b2a76b9719d911017c592",
  "name": "Trojan.Win32.Generic",
  "description": "Тестовая запись об угрозе",
  "threat_type": "trojan",
  "severity": "high",
  "first_seen_at": "2026-01-15T10:30:00Z"
}
```

Отправьте запрос:

```powershell
curl.exe -k -i -X POST https://localhost/info `
  -H "Content-Type: application/json" `
  -H "X-API-Key: $apiKey" `
  --data-binary "@create.json"
```

Успешный ответ — `201 Created` и JSON созданной записи, включая поля времени. Повторная попытка создать запись с тем же MD5 вернёт `409 Conflict`.

### GET `/info/{md5}` — получить угрозу

Возвращает запись по MD5, включая дополнительные поля модели:

```powershell
curl.exe -k -i "https://localhost/info/$md5"
```

Если запись существует, возвращается `200 OK` и JSON с информацией об угрозе. Если MD5 имеет неверный формат — `400 Bad Request`, если запись не найдена — `404 Not Found`.

### PUT `/info/{md5}` — обновить угрозу

Заменяет изменяемые поля существующей записи. MD5 указывается в URL и не меняется. Создайте файл `update.json`:

```json
{
  "name": "Trojan.Win32.Updated",
  "description": "Обновлённое описание угрозы",
  "threat_type": "trojan",
  "severity": "critical",
  "first_seen_at": "2026-01-15T10:30:00Z"
}
```

Отправьте запрос:

```powershell
curl.exe -k -i -X PUT "https://localhost/info/$md5" `
  -H "Content-Type: application/json" `
  -H "X-API-Key: $apiKey" `
  --data-binary "@update.json"
```

При успешном обновлении возвращается `200 OK` и JSON обновлённой записи. Если запись с таким MD5 отсутствует, возвращается `404 Not Found`. PUT не создаёт новую запись.

### Ошибки

| Код | Когда возвращается |
|---|---|
| `400` | Неверный MD5, некорректный JSON или недопустимые поля |
| `401` | Отсутствует или неверен API-ключ при операции записи |
| `404` | Угроза не найдена |
| `409` | Запись с таким MD5 уже существует при POST |
| `429` | Превышен лимит запросов |
| `500` | Внутренняя ошибка сервера |

Ошибки приложения возвращаются в JSON с полем `message` и, при необходимости, `details`. Дополнительные статусы от Nginx и маршрутизатора возможны для неподдерживаемых запросов.

## Защита

- **HTTPS.** Nginx принимает запросы на порту 443 и перенаправляет HTTP-запросы на HTTPS. Для локального запуска используется самоподписанный сертификат.
- **API-ключ.** POST и PUT требуют заголовок `X-API-Key`. Ключ задаётся в `.env` и передаётся контейнеру API через Docker Compose.
- **Rate limiting.** На уровне Go-приложения действует ограничение 10 запросов в секунду на IP с `burst = 20`.
- **Валидация.** Проверяются MD5, название, тип угрозы и уровень опасности. Размер тела JSON ограничен 1 МиБ; неизвестные поля отклоняются.
- **Доверенный прокси.** Приложение принимает клиентский IP из `X-Real-IP` только от настроенного доверенного прокси.
- **Тайм-ауты.** HTTP-сервер ограничивает время чтения и записи запросов.

Конфигурация предназначена прежде всего для локальной проверки тестового задания.

## Тестирование

Для запуска Go-тестов потребуется установленный Go версии, указанной в `go.mod`.

```powershell
go test -count=1 ./...
go vet ./...
```

В проекте есть unit-тесты доменной модели, сервисного слоя, HTTP-обработчиков и middleware. Интеграционные тесты репозитория используют настоящую PostgreSQL.

Чтобы запустить интеграционные тесты, нужна доступная **отдельная тестовая база**. Если `DATABASE_URL` не задан, тесты репозитория, которым требуется БД, могут пропускаться.

```powershell
docker compose up -d postgres

$env:DATABASE_URL = "postgres://threat_user:ВАШ_ПАРОЛЬ@localhost:15432/threats_db?sslmode=disable"

go test -count=1 -v ./internal/repository/...
```

Строку подключения нужно адаптировать под свою тестовую БД и значения из `.env`. Если пароль содержит специальные символы URL, их нужно корректно закодировать. Не запускайте тесты, которые изменяют данные, на рабочей базе.

## Структура проекта

```text
api/                   OpenAPI-спецификация
cmd/server/            Точка входа и сборка зависимостей
internal/domain/       Модель угрозы и правила валидации
internal/handler/      HTTP-обработчики, маршруты и middleware
internal/service/      Бизнес-операции с угрозами
internal/repository/   SQL-запросы и доступ к PostgreSQL
migrations/            Создание таблицы угроз
nginx/                 Конфигурация HTTPS-прокси
compose.yaml           Запуск контейнеров
Dockerfile             Сборка Go-приложения
.env.example           Шаблон конфигурации без секретов
```

Локальные `.env` и `certs/` не должны попадать в репозиторий.
